# Лабораторная работа №2 — Хеш-таблица и Бинарное дерево как индексы

Курс: «Информатика (организация и поиск данных)», 3 семестр.

Реализация двух структур данных (хеш-таблицы с цепочками и бинарного дерева поиска) для использования их в качестве индексов при поиске по атрибутам набора данных. Проект включает построение индексов, точечный и диапазонный поиск, а также замеры производительности (бенчмарки) для сравнения структур на разных объемах данных.

## Архитектура и логика работы

### 1. Базовые структуры (DynamicArray, IDictionary)
- **`DynamicArray`**: Собственный динамический массив (полная замена `std::vector`). Используется для хранения исходных данных и внутренних структур (например, цепочек или стека).
- **`IDictionary`**: Абстрактный интерфейс словаря. От него наследуются `HashTable` и `BinaryTree`, что позволяет использовать их взаимозаменяемо в шаблонных функциях индексации. Метод `GetCapacity()` имеет реализацию по умолчанию (возвращает `GetCount`), которую дерево не переопределяет, так как у него нет понятия «корзин».

### 2. Хеш-таблица (`HashTable`)
- Использует метод цепочек для разрешения коллизий. Корзины хранятся в `DynamicArray`, а сами элементы — в односвязном списке.
- **Масштабирование**: Реализован рост и сжатие таблицы. При достижении количества элементов равному количеству корзин (load factor = 1.0), таблица перестраивается (`Rebuild`).
- **Копирование**: Реализовано глубокое копирование узлов (через оператор присваивания и конструктор копирования).
- **Параметры**: Для настройки перестройки используются понятные имена `shrinkLoadFactor_` (порог сжатия) и `growFactor_` (во сколько раз расти).

### 3. Бинарное дерево поиска (`BinaryTree`)
- **Итеративность**: Все операции (Add, Remove, FreeAll, обходы) написаны без рекурсии с использованием собственного стека (`DynamicArray`). Это защищает от Stack Overflow на вырожденных деревьях.
- **Балансировка**: Чтобы дерево не вырождалось на упорядоченных данных, реализована периодическая перестройка. Если высота превышает `4 * log2(N + 1) + 1`, дерево собирается в идеально сбалансированное из середины In-order массива.
- **Обходы (Traverse)**: Реализованы все 6 видов обхода (КЛП, ЛКП, ЛПК и их зеркальные варианты) через паттерн «Посетитель» (Visitor). Логика обхода отделена от логики обработки (лямбды).
- **Копирование**: Глубокое копирование структуры (сохраняется форма дерева).

### 4. Логика индексов (`Index.h`)
Индексы строятся поверх интерфейса `IDictionary`. Структура `IndexPair` хранит два индекса одновременно: `HashTable` и `BinaryTree`.
- **Точечный поиск (`FindByKey`)**: Ищет ключ через индекс. В хеш-таблице работает за O(1), в дереве — за O(log N).
- **Диапазонный поиск (`FindRangeTree`)**: Доступен только для дерева (через обход `ForEachInRange`). В хеш-таблице диапазон ищется полным перебором (`FindRangeHashScan`), так как хеш не хранит порядок элементов.
- **Линейный поиск (`LinearFind`)**: Используется как эталон для проверки корректности работы индексов (результаты всех трех способов должны совпадать).

### 5. Замеры производительности (`Benchmark.h`, `Timer.h`)
- Сравнивается время построения индекса, точечного поиска (в микросекундах на запрос) и поиска по диапазону.
- Для честных замеров используется медиана из нескольких прогонов (`MeasureMedianMs`), чтобы сгладить влияние операционной системы. Результаты сохраняются в `.csv` файлы для построения графиков.

## Тестирование

Тесты покрывают как базовые структуры, так и их совместную работу:
- **Хеш-таблица**: проверка перестройки (роста/сжатия), обработка коллизий (с помощью константной хеш-функции), глубокое копирование.
- **Дерево**: проверка удаления (листья, узлы с 1 и 2 потомками), проверка всех 6 обходов, проверка балансировки (на 5000 упорядоченных элементов высота остается < 100), глубокое копирование.
- **Индексы**: проверка того, что результаты поиска по хешу, дереву и линейному поиску совпадают (через `SameContent`), а также работа с составными ключами и пустыми данными.

*Все тесты пройдены успешно (`провалов 0`).*

## Выводы по замерам (Бенчмарки)

1. **Построение**: Хеш-таблица строится быстрее дерева, так как вставка в среднем занимает O(1), а в дереве — O(log N) с периодическими перестройками.
2. **Точечный поиск**: Хеш-таблица значительно опережает дерево (O(1) против O(log N)), но дерево выигрывает у линейного поиска (O(log N) против O(N)).
3. **Диапазонный поиск**: Здесь дерево вне конкуренции. Благодаря упорядоченности и отсечению ветвей (`ForEachInRange`), поиск диапазона занимает O(log N + K). Хеш-таблица вынуждена перебирать все элементы, что дает O(N), а линейный поиск по исходному массиву также работает за O(N).
